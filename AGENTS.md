# AGENTS.md

Durable repository guidance for Codex and other coding agents.

Keep this file compact. Put one-off task instructions, audit prompts, and
temporary plans in the task that needs them.

## Project Purpose

This repository packages a classroom-ready Arduino Nano 33 BLE Sense plus
phyphox kit. It maintains one canonical Arduino BLE sketch, generated core
phyphox experiments for that sketch, and a separate curated astronomy experiment
subtree for classroom analogies and bounded model experiments.

## Important Directories

- `arduino/phyphox_ble_sense/` - canonical Arduino BLE firmware.
- `src/phyphox/` - source XML for generated core sensor experiments.
- `src/phyphox/includes/` - shared XInclude XML fragments.
- `experiments/*.phyphox` - committed generated core experiments for import into
  phyphox.
- `experiments/astronomy/*.phyphox` - hand-edited astronomy classroom files;
  these are not generated by `scripts/build-phyphox.sh`.
- `experiments/phyphox_constants.json` - BLE UUID and mode metadata.
- `tools/` - XML post-processing and phyphox validation helpers.
- `scripts/` - build, validation, Arduino compile, security, and local CI
  entrypoints.
- `tests/` - pytest guardrails for XML, generated parity, physics, astronomy,
  and repository contracts.
- `docs/` - runbook, CI notes, repository map, and classroom companion docs.

## Agent Operating Boundaries

Permission boundaries: sensitive actions need explicit user approval from the
user. This includes commits, pushes, pull requests, dependency additions, Cloud
imports/reanalysis, destructive file operations, and marking scanner findings
false positive or suppressed.

## Commands

Install test dependencies:

```sh
python3 -m pip install -r requirements-test.txt
```

Build and generated-file checks:

```sh
make build
bash scripts/build-phyphox.sh
bash scripts/check-generated-clean.sh
```

Tests:

```sh
make test
pytest
```

Lint and format check:

```sh
make lint
ruff check .
ruff format --check .
```

Validation, compile, security, and full local CI:

```sh
make validate
make compile
make security
make ci-local
bash scripts/ci-local.sh
```

`make compile` and `scripts/compile-arduino.sh` require `arduino-cli` and compile
for `arduino:mbed_nano:nano33ble`. XML validation and builds require `xmllint`.

## Runtime Entry Points

- Arduino firmware: `arduino/phyphox_ble_sense/phyphox_ble_sense.ino`.
- Core generated phyphox experiments: `experiments/*.phyphox`.
- Core source XML: `src/phyphox/*.phyphox.xml`.
- Astronomy classroom experiments: `experiments/astronomy/*.phyphox`.
- Full local verification: `scripts/ci-local.sh`.

## Contracts

- BLE device name is `phyphox-sense`.
- BLE UUIDs must stay aligned across `experiments/phyphox_constants.json`,
  `src/phyphox/*.phyphox.xml`, generated `experiments/*.phyphox`, and
  `arduino/phyphox_ble_sense/phyphox_ble_sense.ino`, unless the task explicitly
  changes and documents the BLE contract.
- The data characteristic payload is 5 little-endian `float32` values: device
  time plus four mode-dependent channels. Phyphox packet time is app-managed.
- Core experiment mode IDs are `1` acceleration, `2` gyroscope, `3`
  magnetometer, `4` pressure, `5` temperature/humidity, `6` light/RGB, and `9`
  analog input. Modes `7` and `8` are reserved.
- `experiments/*.phyphox` are generated artifacts. Edit
  `src/phyphox/*.phyphox.xml` and rebuild unless the generator or committed
  artifact contract itself is the target.
- `experiments/astronomy/*.phyphox` are hand-edited and must keep English root
  locale plus `de` and `fr` translation blocks, unless the task explicitly
  changes and documents the astronomy locale contract.
- Astronomy files currently use phone sensors, TI SensorTag hardware, or the
  supported Owon multimeter. Do not route them through the Arduino
  `phyphox-sense` runtime unless the runtime contract is deliberately changed
  and documented.
- Arduino package and library versions in `scripts/compile-arduino.sh` are pinned
  for reproducible classroom builds. Do not upgrade them without running the
  relevant compile and experiment validation checks.

## Deprecated-Code Policy

Do not keep deprecated compatibility paths unless there is evidence they are
still required. Do not silently preserve old behavior if it is wrong; document
the compatibility impact and verification path. Do not remove pre-existing
deprecated code, archived audit files, or old compatibility material unless the
task explicitly includes that cleanup.

## Code-Change Rules

Act as a cautious senior engineer.

- Prefer the minimum code that solves the actual problem.
- No speculative features.
- No abstractions for single-use code.
- No broad rewrites without a written plan.
- Touch only files required by the task.
- Read relevant files, exports, callers, tests, shared utilities, scripts, and
  docs before editing.
- Do not assume dependencies, code paths, config, schemas, APIs, protocols, or
  storage contracts exist. Inspect them.
- Keep generated and hand-edited experiment surfaces distinct.
- Keep tests focused on why behavior matters, not only what output appears.
- Report unrelated issues instead of fixing them.

## Verification Expectations

Use the narrowest meaningful check first, then broader checks as risk increases.
For source XML or generated experiment changes, run `bash scripts/build-phyphox.sh`
and `bash scripts/check-generated-clean.sh`. For BLE, mode, or file-contract
changes, run targeted pytest coverage and `bash scripts/validate-xml.sh`. For
firmware changes, run `bash scripts/compile-arduino.sh` when `arduino-cli` is
available. Before PR-ready handoff, prefer `bash scripts/ci-local.sh`.

Do not claim completion without evidence. If any build, test, lint, migration,
edge case, hardware probe, or runtime check was skipped, say so explicitly.

## Final Response Expectations

For implementation tasks, include:

1. Files changed.
2. Why each file changed.
3. Commands run.
4. Tests/checks passed.
5. Tests/checks skipped or unavailable.
6. Remaining uncertainty.
7. Follow-up risks.
